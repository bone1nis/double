# CLAUDE.md

Правила работы над проектом. Описание продукта, функциональность и запуск - в [README.md](README.md).

## Стек

React 19, TypeScript (strict), Vite, SCSS (БЭМ), Zustand + persist, Yup, dnd-kit, Motion, SVGR, ESLint, Prettier, Vitest, Husky + lint-staged. Менеджер пакетов - pnpm. Нужен Node ≥ 20.19 (`nvm use`).

Минимум зависимостей: не добавлять пакеты и не менять архитектуру без необходимости.

## Структура (Feature-Sliced Design)

Слои сверху вниз: `app` → `pages` → `widgets` → `features` → `entities` → `shared`. Слой импортирует только нижележащие; слайсы одного слоя не импортируют друг друга. Публичный API слайса - `index.ts`, импорт через алиас `@/`. Внутри слайса сегменты: `ui/` (компоненты), `model/` (логика, типы, хуки, тесты), `config/` (константы). Константы не кладём в `ui/`.

- `src/app/` - точка входа, глобальные стили (SCSS) и токены дизайна.
- `src/pages/` - страницы: композиция виджетов и общее состояние между ними (например, id открытой задачи).
- `src/widgets/` - самостоятельные блоки интерфейса: `todo-board` (форма, фильтры, список), `todo-panel` (боковая панель задачи). Виджеты не импортируют друг друга.
- `src/features/` - пользовательские сценарии: `add-todo`, `filter-todos`, `search-todos`, `edit-todo`, `reorder-todos`, `undo-delete`, `clear-completed`, `toggle-theme`.
- `src/entities/todo/` - тип задачи, операции, даты, валидация, стор, синхронизация вкладок и доменные компоненты (`TodoItem`, `PriorityBadge`, `PrioritySelect`, `DueLabel`, `DuePicker`, `ProgressRing`).
- `src/shared/` - `ui/` (Button, Input, Textarea, Checkbox, Tabs, Calendar, Popover, Drawer, Kbd, EmptyState), `lib/` (хелперы, даты, `useHotkey`), `assets/icons/` (SVG-файлы, в код попадают через SVGR: `import { PlusIcon } from '@/shared/assets'`). Без знания о домене.

Если логика нужна двум виджетам, её выносим вниз (в фичу или сущность), а не импортируем один виджет из другого.

## Принципы

- Небольшие компоненты с одной ответственностью; логика отдельно от представления: операции, фильтры, даты, парсеры - чистые функции в `model/`.
- UI-компоненты в `shared/ui` переиспользуемы и не импортируют доменный код.
- Новые пользовательские сценарии - отдельной фичей, а не правкой чужого слайса.

## Компоненты и функции

- Каждый компонент - отдельная папка: `Name/Name.tsx`, `Name/Name.scss` (если нужны стили), `Name/index.ts`.
- Функции и компоненты объявлять через `const` (стрелочные), без `function`.
- Без комментариев в коде, если они не необходимы; названия тестов - на русском.

## TypeScript

- Никакого `any`; `unknown` + сужение типов для внешних данных (`localStorage`).
- Явные типы для публичных интерфейсов (props, возвращаемые значения экспортируемых функций).
- Без небезопасных приведений (`as`, `!`), в том числе в тестах - использовать type guards или типизированные аннотации.

## React

- Только функциональные компоненты и хуки.
- Не дублировать состояние: производные значения вычислять, а не хранить.
- Зависимости эффектов указывать корректно, не подавлять `react-hooks/exhaustive-deps`.
- Состояние формы или поля, которое должно сбрасываться при смене сущности, сбрасываем через `key`, а не эффектом.

## Данные и хранение

- Задачи хранятся через `zustand` + `persist` в `localStorage`; всё прочитанное проходит через `sanitizeTodos` (Yup), некорректные записи отбрасываются.
- Новое поле задачи: добавить значение по умолчанию в `sanitize`, чтобы старые данные не ломались, и покрыть это тестом.
- Правки задачи отправляем патчем только изменённых полей, чтобы не затирать изменения из другой вкладки.

## UI и дизайн

- Макет и токены взяты из Claude Design; цвета, радиусы и тени - только через CSS-переменные из `app/styles/global.scss`, без хардкода. Шрифт - Golos Text.
- Тёмная тема переопределяет только переменные (`data-theme="dark"`).
- Семантический HTML, доступность с клавиатуры, `aria-*` где нужно. Состояния hover / focus-visible / active / disabled у всех интерактивных элементов.
- Поля ввода без синих колец фокуса: при фокусе рамка просто темнеет.
- Всплывающие окна делаем через `Popover` (портал, сам выбирает сторону, закрывается по `Esc` и клику снаружи, возвращает фокус). Панель - через `Drawer` (блокирует прокрутку страницы, делает `#root` недоступным через `inert`).
- Адаптивность: проверять десктоп и ширину до 375px (брейкпоинт 640px); на мобильной ширине ничего не обрезается и не сжимается.
- Анимации появления и скрытия окон, панелей и тостов - через `motion` (`m` + `AnimatePresence`), а не вручную на CSS. Строки списка анимируются на CSS, чтобы не мешать перетаскиванию. Уважаем `prefers-reduced-motion`.

## Тесты

Тестируем бизнес-логику и критические сценарии: операции, фильтры, даты, валидацию, хранилище, повреждённые данные, быстрый ввод, отмену удаления. Детали вёрстки не тестируем. Любой новый синтаксис быстрого ввода или правило парсинга - с тестами.

## Перед завершением изменений

Обязательно запустить и добиться успеха: `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm build`. Для изменений интерфейса дополнительно проверить результат в браузере (обе темы, десктоп и мобильная ширина).
