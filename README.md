# Doable

Doable - список задач на React + TypeScript. Добавление, отметка выполненных, удаление и сохранение после обновления страницы, а также приоритеты, сроки, описания, поиск, фильтры, боковая панель задачи, быстрый ввод и отмена удаления.

- **Рабочий сайт:** _добавлю ссылку после деплоя на Netlify_
- **Код:** этот репозиторий

## Как делался проект

Проект сделан с помощью AI. Я ставила задачи и принимала решения, а AI писал код и делал макет.

**Что делала я**

- **Требования.** Разобрала ТЗ и решила, что добавить сверх него.
- **Архитектура и стек.** Выбрала архитектуру и весь стек: FSD, React, TypeScript, Zustand, Yup, SCSS. Задала правила для ассистента в [CLAUDE.md](CLAUDE.md).

- **Проверка.** Смотрела результат в браузере и возвращала на доработку.

## Функциональность

**По ТЗ**

- Добавление задач: поле ввода, кнопка, Enter
- Отметка выполненных, выполненные визуально отличаются
- Удаление задач
- Сохранение в `localStorage` после обновления страницы
- Пустые и состоящие из пробелов задачи добавить нельзя

**Сверх ТЗ**

- Боковая панель задачи (как в трекерах): клик по задаче открывает название, описание, статус, приоритет, срок, дату создания и удаление; `Esc` закрывает
- Описание задачи (до 500 символов): поле прямо в форме добавления (`Ctrl/Cmd+Enter` добавляет), редактируется в панели, в списке показывается под названием
- Быстрый ввод: срок и приоритет можно написать прямо в названии, например `позвонить маме завтра !высокий`. Понимает «сегодня», «завтра», «послезавтра», «через неделю», «через 3 дня», `12.11`, `12.11.2027` и `!высокий` / `!средний` / `!низкий`. Распознанное показывается в поле, а из названия убирается. Рядом со сроком есть кнопка «?» с мини-гайдом: синтаксис и примеры, которые вставляются в поле по клику
- Приоритет (низкий / средний / высокий): точка с подписью в строке, меняется кликом
- Срок выполнения: «Сегодня», «Завтра», подсветка просроченных; свой календарь с быстрыми вариантами и управлением стрелками, окна сами выбирают сторону, где хватает места
- Фильтры по статусу и по приоритету, поиск по названию и описанию с подсветкой совпадений, всё работает вместе
- Отмена удаления: тост с таймером для одной задачи и для очистки выполненных, задачи возвращаются на прежние места
- Перетаскивание для изменения порядка, в том числе с клавиатуры
- Кольцо прогресса и подпись «Осталось N задач» в шапке
- Горячие клавиши: `N` - новая задача, `/` - поиск, `Esc` очищает поиск или закрывает панель
- Синхронизация между вкладками
- Миграция старых данных: записи без приоритета, срока и описания достраиваются значениями по умолчанию
- Проверка по ходу ввода: ошибка и счётчик символов появляются сразу, не дожидаясь ухода из поля (название до 120 символов, описание до 500)
- Светлая и тёмная темы с сохранением выбора, без мигания при загрузке
- Плавное открытие и закрытие панели, всплывающих окон и тоста (библиотека motion), с учётом `prefers-reduced-motion`
- Разные пустые состояния, адаптивная вёрстка

## Стек

React 19 · TypeScript · Vite · SCSS · SVGR · Zustand · Yup · dnd-kit · Motion · ESLint (typescript-eslint, react, react-hooks) · Prettier · Vitest

`dnd-kit` нужен только для перетаскивания задач, `motion` - для анимации появления и скрытия окон.

## Установка и запуск

Требуется Node ≥ 20.19 (см. `.nvmrc`: `nvm use`) и [pnpm](https://pnpm.io).

```bash
pnpm install
pnpm dev            # dev-сервер
pnpm build          # проверка типов + production-сборка
pnpm preview        # просмотр сборки
pnpm lint           # ESLint
pnpm typecheck      # tsc
pnpm test           # Vitest
pnpm format         # Prettier
```

## Архитектура

Слои `app → pages → widgets → features → entities → shared`, импорты только сверху вниз, внешний доступ к слайсу - через его `index.ts`. Алиас `@/` указывает на `src/`.

```
src/
├─ app/                   вход, глобальные стили и токены дизайна (SCSS)
├─ pages/
│  └─ home/               страница HomePage
├─ widgets/
│  ├─ todo-board/         доска: форма, фильтры, поиск, список
│  └─ todo-panel/         боковая панель задачи: название, описание, статус, приоритет, срок
├─ features/
│  ├─ add-todo/           добавление задачи (текст, описание, приоритет, срок, быстрый ввод)
│  ├─ search-todos/       поиск по названию и описанию (клавиша /)
│  ├─ filter-todos/       фильтры по статусу и приоритету
│  ├─ edit-todo/          поля названия и описания, показ текста с подсветкой поиска
│  ├─ undo-delete/        «удалить / очистить с отменой»: стор, действия и тост
│  ├─ reorder-todos/      перетаскивание (dnd-kit)
│  ├─ clear-completed/    очистка выполненных
│  └─ toggle-theme/       светлая / тёмная тема
├─ entities/
│  └─ todo/               тип Todo, операции, даты, валидация, стор (zustand + localStorage),
│                         синхронизация вкладок, TodoItem, PriorityBadge, PrioritySelect,
│                         DueLabel, DuePicker, ProgressRing
└─ shared/
   ├─ ui/                 Button, Input, Textarea, Checkbox, Tabs, Calendar, Popover, Drawer, Kbd, EmptyState
   ├─ lib/                общие хелперы (даты, сетка календаря, useHotkey, pluralize)
   └─ assets/icons/       SVG-файлы, подключаются как React-компоненты (SVGR)
```

Стили - SCSS (БЭМ-именование) рядом с компонентами; общие токены - CSS-переменные в `app/styles/global.scss`. Бизнес-логика (`model/`) не зависит от React и покрыта тестами.

## Принятые решения

- **Выбор открытой задачи хранится на странице.** Виджеты доски и панели не импортируют друг друга (правило FSD), поэтому `HomePage` связывает их: передаёт доске `onOpen`, а панели - `todoId`. Общая логика отмены удаления вынесена в фичу `undo-delete`, чтобы её вызывали оба виджета.
- **FSD** - задел на рост: новая функциональность добавляется отдельной фичей и не трогает существующий код, а правило «импорт только вниз» не даёт слоям переплетаться. Для задачи такого размера это чуть больше структуры, чем нужно, но она окупается при расширении.
- **Логика отдельно от интерфейса** - операции над задачами, валидация, фильтры и даты - чистые функции, их проверяют тесты без React и браузера.
- **Zustand + `persist`** - вместо самописной работы с `localStorage`: меньше кода, сохранение и восстановление работают из коробки.
- **Yup** - одна библиотека и для проверки ввода, и для проверки данных, прочитанных из `localStorage`.
- **Защита от испорченных данных** - после загрузки записи проверяются схемой, некорректные отбрасываются, а старые достраиваются значениями по умолчанию. Испорченный `localStorage` не ломает приложение.
- **Свои компоненты на нативных элементах** - `button`, `input`, `label` по умолчанию доступны с клавиатуры и скринридерам; оформление полностью своё. Календарь, всплывающие окна и панель написаны без библиотек.
- **Всплывающие окна через портал** - календарь и меню не обрезаются границами списка и сами выбирают сторону, где хватает места.
- **SCSS + CSS-переменные** - цвета заданы токенами, тёмная тема переопределяет только переменные.
- **Анимации через motion.** Появление и особенно _скрытие_ панели, всплывающих окон и тоста нельзя нормально сделать на CSS, потому что элемент сразу пропадает из DOM. `motion` (`LazyMotion` + `AnimatePresence`) держит его до конца анимации. Строки списка анимируются на CSS, чтобы не мешать перетаскиванию. `prefers-reduced-motion` учитывается глобально.

## Качество и деплой

- **Husky**: `pre-commit` запускает lint-staged (ESLint + Prettier по изменённым файлам), `pre-push` - typecheck и тесты.
- **GitHub Actions** (`.github/workflows/ci.yml`): lint, format:check, typecheck, test, build на каждый push в `main` и PR.
- **Netlify**: сайт собирается автоматически при каждом пуше в подключённый репозиторий (настройки в `netlify.toml`: `pnpm build`, публикация `dist`).

## Планы на развитие

- Линтер границ слоёв (`eslint-plugin-boundaries` или Steiger), чтобы правила FSD проверялись автоматически.
